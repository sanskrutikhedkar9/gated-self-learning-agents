# AppWorld benchmark-readiness review

## Verdict

The blocking implementation work is complete. The repository is ready for a
**one-task paid smoke run followed by train/dev**, provided preflight is green.
It is not yet evidence of AppWorld performance: no treatment score is claimed
until frozen baseline/treatment runs and official evaluations are completed.

## Required architecture before the treatment run

### P0. Capture replayable, provenance-bearing traces

Instrument the agent/runtime boundary rather than converting
`api_calls.jsonl`. Each normalized call must contain:

- canonical `app.api` identity and tool-contract hash;
- arguments, returned result, explicit success/error, latency, and provider
  usage;
- stable data-flow identity after secret redaction;
- task/run/model/prompt/config identifiers;
- an official evaluator result loaded from AppWorld's evaluation output.

Do not trust a caller-supplied `passed: true` alone. The strict adapter requires
matching `evaluation.source` and `evaluation.success` fields. The treatment
runner wraps the bundled baseline agent with the rich recorder and uses the
schema-backed registry for learned execution.

### P0. Add an AppWorld treatment runner

The runner must create a fresh world per condition, expose canonical registered
tools with schemas, retrieve a workflow, apply the benchmark's predeclared
confirmation policy, execute, call the official evaluator, and record actual
cost/latency. On workflow failure, either restore the initial world or start a
new one before invoking the baseline agent. Never replay a full agent in a
partially mutated world.

Implemented in `experiments/appworld/treatment_runner.py`. Official evaluator
failure is a final score, not a fallback signal; only observable execution
failure can select the fresh-world fallback.

### P1. Replace flat traces with typed control flow

AppWorld solutions commonly paginate, filter, branch, aggregate, and mutate a
data-dependent number of objects. Collapsing these runs into a long fixed API
sequence is not a reusable program. Add at least `map/for_each`, `while_page`,
`filter`, `reduce`, and explicit postconditions, or compile successful code into
a restricted audited program representation. Promotion should compare program
structure, not raw request count.

Implemented as bounded `paginate`, `foreach`, `filter`, `reduce`, and `branch`
nodes. Pagination is also normalized during structural discovery and induced
from repeated page calls by the deterministic compiler.

### P1. Constrain model-based induction and matching

The model now proposes structure rather than merely naming a deterministic
draft, but it has no execution or publication authority. Its input contains
templated instructions, symbolic data-flow references, result shapes, and tool
contracts instead of concrete stored argument/result values. Local validation
rejects unobserved tools, schema violations, invalid/forward references,
unsupported predicates/reducers, unbounded loops, redacted literals, and
capability mismatches. Every source episode is replayed with recorded results;
failed proposals receive at most two sanitized repair attempts and otherwise
fall back to the deterministic compiler or remain candidate.

Family discovery and request matching use a model only after deterministic
scope, side-effect, status, environment, tool-availability, and negation gates.
Published programs are immutable: new structural evidence creates a challenger
that must pass shadow promotion before retiring an incumbent.

### P1. Predeclare a valid evaluation protocol

Use the official TGC and SGC metrics. Train/induce on `train`, tune thresholds
on `dev`, then freeze all learning and thresholds for `test_normal` and
`test_challenge`. If official evaluator feedback is used to learn between test
tasks, report that separately as an online-oracle-feedback condition; it is not
comparable to a standard agent that does not receive test labels.

Run paired baseline and treatment worlds with identical agent/model/tool
access. Report evaluator success, workflow offer precision, fallback rate,
actual provider usage, total compiler/extractor/fallback cost, p50/p95 latency,
and confidence intervals. Do not optimize against test task content or ground
truth.

Before collecting paper numbers, commit/tag the implementation while leaving
protected AppWorld assets ignored, freeze both the agent and AppWorld
environments, and record the source commit, AppWorld/data versions, model
identifier, prompt/config hash, and random seed in every run manifest.

## Fail-fast commands

Audit a split and existing native output without printing secrets:

```powershell
python -m experiments.appworld.preflight `
  --dataset data/datasets/dev.txt `
  --native-outputs experiments/outputs/YOUR_EXPERIMENT
```

Audit rich normalized records before ingestion:

```powershell
python -m experiments.appworld.preflight `
  --dataset data/datasets/dev.txt `
  --records outputs/appworld_records.jsonl
```

Use the complete commands in `experiments/appworld/README.md`. Do not proceed to
a paid treatment run while preflight reports blockers. A zero-route run can
validate integration, but it cannot support the model-shedding claim.
